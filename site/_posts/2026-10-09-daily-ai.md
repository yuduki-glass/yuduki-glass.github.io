# トマさんAI速報 2026年10月9日

今日のAI界隈を一言でまとめるなら、**「賢いチャットを作る競争」から「仕事を最後までやる環境を作る競争」へ、かなり露骨に軸が移った日**です。

モデル単体のベンチマークだけ追っていると、この変化を取り逃がします。GPT-6のIntelligent UI、GoogleのGemini Agent、Claudeの低価格モデル、MCP、エージェント用サンドボックス、長期記憶。バラバラに見える発表が、実は全部「AIに仕事を任せるための周辺設備」という一本の線でつながっています。

以下、実際に使えそうなものを優先して整理します。

## 1. GPT-6のIntelligent UI：回答そのものが「小さなアプリ」になり始めた

**確度：高（OpenAI公式）**

### 何が話題？
OpenAIは10月7日、ChatGPTでGPT-6とIntelligent UIの展開を開始しました。従来の文章中心の回答だけでなく、比較表示、図、計算機、操作可能なUIなどを、質問に応じてChatGPT側が選んで生成します。

### 何ができる？
これまでの生成AIは「文章を返す」が基本でした。Intelligent UIでは、たとえば比較なら比較表、計算なら計算機、選択が必要なら操作できる部品、といった具合に**答えの形式そのものをAIが設計**します。

### どう使う？
無理に「表にして」「グラフにして」と細かく指定するより、まず目的をそのまま渡す方が面白いです。

例：

> この3案の違いを、意思決定しやすい形で比較して。

出力形式までAIに考えさせる使い方です。

### 料金・制限・罠
Plus、Pro、Business、Enterpriseから展開され、Free/Goにも順次拡大。すべての回答が派手なUIになるわけではなく、普通の文章が適切なら文章のままです。

### トマさん一言
**「AIに文章を書かせる」から「AIに画面を作らせる」への変化。** 地味に見えて、これはかなり大きいです。

情報源：OpenAI ChatGPT Release Notes  
https://help.openai.com/en/articles/6825453-chatgpt-release-notes

## 2. Codexが実行中の方向修正に強くなった

**確度：高（OpenAI公式）**

### 何が話題？
10月8日のChatGPTリリースノートで、デスクトップ版Codexの「steering」が高速化されたことが発表されました。

### 何ができる？
Codexが長い作業をしている途中で、

> そこは触らないで

> やっぱりCSV出力も追加して

> その方法ではなく既存関数を使って

といった追加指示を入れやすくなります。

### どう使う？
最初から完璧な巨大プロンプトを作るより、**まず仕事を渡し、途中で監督する**使い方が現実的になります。

設定では、追加メッセージを現在実行中のタスクへ反映するか、次の処理まで待たせるかも選べます。

### トマさん一言
人間の部下に仕事を頼むときも、最初に仕様書400ページを渡して黙って完成を待つ会社はだいたい何かがおかしい。AIも同じ方向へ来ています。

情報源：OpenAI ChatGPT Release Notes  
https://help.openai.com/en/articles/6825453-chatgpt-release-notes

## 3. Googleが「Gemini Agent」を発表。Workspaceの中で仕事を終わらせる方向へ

**確度：高（Google公式）**

### 何が話題？
Google Cloudは10月8日、仕事向けの汎用エージェント「Gemini agent」を発表しました。

### 何ができる？

### どう見るべき？
ChatGPT Work、Codex、Gemini Agentなどを見ると、2026年後半の主戦場は明確です。

「一番賢いチャットはどれか」ではなく、

**「どのAIに仕事の入口と出口を握らせるか」**

になっています。

### トマさん一言
AI専用画面へ毎回コピペする時代が終わり、AIが既存業務の中へ入ってくる段階です。

情報源：Google Blog

## 4. Claude Haiku 5.5：小型モデルが「安いから我慢して使うもの」ではなくなる

**確度：高（Anthropic公式）**

### 何が話題？
Anthropicは10月7日、Claude Haiku 5.5を発表。Haiku 4.5より平均約75%低い実行コストをうたい、要約、分類、DB問い合わせ、サブエージェントなど大量処理向けに位置付けています。

### 何ができる？
高性能モデル1体ですべて処理するのではなく、

- 難しい判断 → Opus / Sonnet級
- 大量の単純処理 → Haiku

という役割分担がしやすくなります。

### 実務で重要な点
エージェントは一つの仕事で何十回、何百回とモデルを呼ぶことがあります。そのため「1回の回答能力」だけでなく、**小さな処理をいくらで大量に回せるか**が重要になります。

### トマさん一言
AIも組織化が始まりました。部長一人にコピー取りから経営判断まで全部やらせるより、仕事を分けた方が当然まともです。

情報源：Anthropic  
https://www.anthropic.com/claude-haiku-5-5

## 6. AnthropicがOSS Scannerを発表。AIでオープンソースの脆弱性を探す

AnthropicはCyber Missionの一環として、オープンソースプロジェクトを強力なモデルで定期スキャンする「OSS Scanner」を発表しました。

### 何ができる？

### なぜ重要？

### トマさん一言
生成AI時代は「書くAI」だけ導入すると危ない。レビュー、テスト、監査までセットで自動化して初めて帳尻が合います。

## 7. Docker Cloud Sandboxes：AIに仕事を任せるなら「隔離された作業場」を渡す

**確度：高（Docker公式）**

### 何が話題？
DockerはCloud Sandboxesを展開しています。ローカルで始めたエージェント作業をDocker管理のクラウドmicroVMへ移し、ノートPCを閉じても長時間タスクを継続できます。

### 何ができる？
AIエージェントへシェルやファイル操作を許すと便利ですが、同時に怖い。Sandboxでは、AIを隔離した環境で動かし、アクセス範囲を限定できます。

### 実践的な意味
今後のエージェント運用では、

**AIモデル + ツール + 権限管理 + Sandbox**

までが一つのセットになりそうです。

### トマさん一言
「AIが賢くなれば全部解決」ではありません。賢いものほど、ちゃんと檻が要る。人間社会が数千年かけて学んだことをAIでも繰り返しています。

情報源：Docker  
https://www.docker.com/blog/docker-cloud-sandboxes-wearedevelopers-recap/

## 9. claude-memが示す「AIエージェントの記憶」を外付けする発想

**確度：中〜高（GitHub公開リポジトリを確認）**

### 何が話題？
GitHub Trendingでは、`thedotmack/claude-mem` が注目されています。セッション中のツール利用や作業内容を保存・圧縮し、次回以降のセッションへ関連情報を戻す仕組みです。

Claude Codeを中心にしつつ、Codex CLIなど複数のホストへの対応も進んでいます。

### 何ができる？
AIとの開発でありがちな、

> 昨日そこ直したじゃん

> その設計にした理由、前に説明したじゃん

問題を、モデル本体の記憶だけに頼らずプロジェクト側で補います。

SQLite、検索、要約などを組み合わせ、必要な過去情報だけを段階的に取得する設計です。

### 料金・制限・罠
オープンソース部分はApache-2.0ですが、利用する記憶プロバイダやモデルによって別途条件が変わります。「無料の記憶装置」と雑に理解せず、導入時に保存先と送信先を確認した方がいいです。

### トマさん一言
今後重要になるのは「一番頭のいいAI」だけではなく、**昨日の仕事をちゃんと覚えているAI**です。

情報源：GitHub  
https://github.com/thedotmack/claude-mem

## 10. cmux：複数のコーディングAIを並列で働かせるための「監督席」

**確度：中〜高（GitHub公開リポジトリを確認）**

### 何が話題？
`manaflow-ai/cmux` は、AIコーディングエージェントを複数同時に動かすことを前提にしたmacOS向けターミナルです。

### 何ができる？
縦タブ、複数ペイン、通知リング、通知一覧などを備え、Claude Code、Codexなど複数のエージェントを並行稼働させたとき「どのAIが人間の判断待ちなのか」を把握しやすくします。

### なぜ重要？
これはAIそのものを賢くするツールではありません。

しかしAIエージェントが複数動くようになると、人間側の問題は、

**「どう指示するか」から「どう監督するか」**

へ変わります。

### 制限
現時点ではmacOS向け。Windows中心の環境なら、そのまま導入するというより「複数エージェントを監督するUI」という発想を知っておく価値があります。

情報源：GitHub  
https://github.com/manaflow-ai/cmux

# 今日の実践：AIを「回答者」ではなく「工程」に入れてみる

今日のニュースを読んで終わりでは少しもったいないので、一つだけ実験するならこれです。

普段AIに、

> この文章を要約して

と頼んでいる仕事を一つ選び、代わりに、

> この作業の最終成果物は○○です。必要な情報確認、整理、成果物作成まで進めてください。途中で判断が必要なところだけ私に確認してください。

と頼んでみる。

ポイントは、**AIへの依頼単位を「質問」から「仕事」に変えること**です。

2026年のAI進化は、モデルのIQ競争だけを見ていると分かりにくくなっています。MCP、プラグイン、Cloud、Sandbox、Memory、Agent UI。周辺技術が急速に育っている理由は全部同じです。

**AIが答えるだけではなく、仕事を引き受け始めたから。**
