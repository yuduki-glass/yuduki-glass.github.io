# 結月硝子 AI速報 2026/10/9(金) 更新

今朝は10月8日〜9日朝の更新を中心に、「今日から使える」「運用を変える価値がある」ものを優先した。派手なモデル発表より、仕事の手数や失敗を減らす情報を上に置いている。今回は6件。

## 1. ChatGPT/Codexを会社で広げるなら「AIに専門家の仕事を手順化させる」がかなり現実的

**情報の確度：** 確認済み

**難易度：** すぐ試せる

### 何が話題？

OpenAIが10月8日、OracleでのChatGPT Work/Codex活用事例を公開した。OracleではChatGPT利用者が13万人、Codex利用者が9.5万人超。採用部門では人材市場調査の所要時間を98％減らしたとしている。重要なのは数字そのものより、「専門家だけができた調査・判断手順を、AIを介して他の担当者でも再利用できる形にした」という運用。

### つまり何ができる？

AIへ単発の質問を投げるより、「この仕事では最初にAを確認し、BとCを比較し、最後にこの形式で出す」という専門家の作業手順を固定した方が、組織では効果が出やすい。

### こんな人に役立つ

同じ調査・確認・資料作成を何度も行う人。新人へ仕事を教える人。属人化した作業を減らしたい人。

### 具体的な使用例

たとえばRPGプログラムの調査なら、「入口パラメータ確認→F仕様確認→SQL/RPGネイティブI/O確認→サブルーチン追跡→更新対象整理→不明点一覧」という読み方を手順として保存する。次回からコードだけ渡して同じ観点で調べさせる。

### 試し方

1. 自分が週1回以上やる作業を1つ選ぶ
2. ChatGPTに「この作業で私が毎回確認していることを、再利用できる標準手順にして」と頼む
3. 出てきた手順を自分で修正
4. 次回はその手順＋新しい材料だけ渡す

### 料金・制限・罠

Oracleの98％削減はOracle自身の事例で、どの会社でも同じ数字になるわけではない。特に判断基準が曖昧な仕事は、手順化しただけで品質が上がるとは限らない。

### 検証するとどこまで本当？

利用人数と削減率、活用例はOpenAI公式のOracle事例で確認済み。ただし効果測定の詳細条件までは公開ページだけでは十分に分からない。

**情報源：** OpenAI「How Oracle turns days of work into minutes with ChatGPT and Codex」（2026年10月8日）

> **結月硝子一言：** AI導入で効くのは「全員に好きにチャットさせる」より、上手い人の仕事の型を再利用する方。AI以前からある標準化の話だけど、AIのおかげで標準化コストがかなり下がった。

## 2. WindowsでCodex CLI 0.161.0を使う人は、CPUによって起動前に落ちる報告あり

**情報の確度：** 確認済みの不具合報告あり

**難易度：** すぐ確認できる

### 何が話題？

10月8日、OpenAI公式GitHubに、Windows 11＋AMD Ryzen 5 8400F環境でCodex CLI 0.161.0が codex.exe --version の段階でクラッシュするIssueが登録された。認証前なので、アカウントやプロジェクト設定より低い層で落ちている。

### つまり何ができる？

WindowsでCodexを安定利用しているなら、0.161.0への更新を「最新版だから」という理由だけで急ぐ必要はない。

### こんな人に役立つ

Windows版Codex CLI利用者。特にAMD CPU環境。

### 具体的な使用例

仕事PCで朝にCodexを更新→起動不能→再インストール大会、という人類が定期開催する祭りを避ける。

### 試し方

1. PowerShellで codex --version を確認
2. 現在正常ならバージョンを控える
3. 更新前にOpenAI CodexのRelease/Issuesを確認
4. 問題が報告されている版へは、必要性がなければ急いで上げない

### 料金・制限・罠

現時点では1件の具体的な再現報告で、「0.161.0はWindows全体で壊れている」とまでは言えない。CPU固有の可能性もある。

### 検証するとどこまで本当？

Issue、環境、エラーコード、再現手順はOpenAI公式GitHubで確認済み。原因は未確定。

**情報源：** OpenAI Codex GitHub Issue #51929（2026年10月8日）

> **結月硝子一言：** 昨日もWindows版の地雷を載せたけど、今日は別の0.161.0報告。Codexを仕事道具にするなら「最新版追従」より「動いている版を記録」が重要になってきた。

## 3. Googleも「AIへ仕事を丸ごと預ける」方向へ。Geminiの仕事用エージェントが登場

**情報の確度：** かなり確からしい。機能の多くは早期提供段階

**難易度：** 現時点では企業・先行利用者向け

### 何が話題？

Googleは10月8日、業務システムをまたいで仕事を進めるGeminiの仕事用エージェントを発表した。単に質問へ答えるだけでなく、目標を渡すと計画し、必要な機能や接続先を使い、クラウド側で仕事を続ける構想。複数段階のバックグラウンド実行や第三者モデル利用など、一部機能はまだ早期提供。

### つまり何ができる？

今後は「Gmailを読むAI」「Docsを書くAI」「コードを書くAI」を別々に操作するより、「この案件を整理して関係者へ共有して」のように目的を渡し、裏側で複数サービスをまたがせる方向が強くなる。

### こんな人に役立つ

Google Workspace中心の会社。メール、資料、予定、業務システム間のコピペが多い人。

### 具体的な使用例

将来的には「昨日の会議内容を確認→関連資料を探す→決定事項をDocsへ整理→担当者向けメール案を作る」といった一連の仕事をまとめて依頼する形が想定される。

### 試し方

現時点では一般利用者が今朝すぐ全部使える機能ではない。Workspace利用者は、まず自分の業務で「アプリ間の手作業」を3つ書き出しておく。エージェント機能が来たとき、そこが自動化候補になる。

### 料金・制限・罠

一般提供日や新エージェント機能の完全な料金体系は今回確認できなかった。発表デモと自分の契約で使える機能を混同しないこと。企業利用では権限管理が本体になる。

### 検証するとどこまで本当？

10月8日の発表と早期提供の制約は複数情報源で一致。一方、すべての紹介機能が全利用者へ提供済みという状態ではない。

**情報源：** Googleの10月8日発表を基にした当日検証記事・製品FAQ確認

> **結月硝子一言：** OpenAI、Google、Anthropicとも、チャット欄の賢さ競争から「仕事を途中で人間へ返さず最後まで運ぶ」競争へ移っている。次に効くのはモデル名より、どの社内サービスへ安全につながるか。

## 4. GPT-6のIntelligent UIは無料ユーザーにも展開開始。説明を「その場で触れる道具」に変えられる

**情報の確度：** 確認済み

**難易度：** すぐ使える

### 何が話題？

OpenAIはGPT-6とIntelligent UIをPlus、Pro、Business、Enterpriseから展開し、10月8日からFree/Goにも拡大すると発表している。回答内にグラフ、ボタン、フォーム、操作可能な要素などを組み込める。

### つまり何ができる？

昨日は有料側中心だったが、今日から無料利用者にも順次広がる。社内で「自分は有料だから使えるが、相手は無料だから再現できない」という壁が少し下がる。

### こんな人に役立つ

計算、比較、教育、説明資料のたたき台をChatGPTで作る人。

### 具体的な使用例

「このRPGのIF/ELSE/DOWの流れを、条件をON/OFFして追える図にして」のように、読むだけでなく操作しながら理解する教材を作らせる。

### 試し方

1. ChatGPTを開く
2. 数値や条件が変化する質問をする
3. 「文章だけでなく、条件を切り替えて確認できる形にして」と追加
4. 表示が出れば実際に値を変える

### 料金・制限・罠

段階展開なので、Free/Goでも今日必ず全員に表示されるとは限らない。有料版と無料版では利用上限やモデルが異なる。

### 検証するとどこまで本当？

OpenAI公式発表でFree/Goへの10月8日からの展開を確認済み。

**情報源：** OpenAI「GPT-6 and Intelligent UI for everyone」（2026年10月7日）

> **結月硝子一言：** Intelligent UIは「すごい画面が出る」より、「説明のためだけにExcelや簡易Webアプリを別で作る必要が減る」と考えた方が実務的。

## 5. AIコーディングでは「会話を長く続ける」より、仕様書を外に残す運用が改めて有力

**情報の確度：** かなり確からしい

**難易度：** すぐ試せる

### 何が話題？

今週公開された比較記事では、GitHub Spec Kit、OpenSpec、BMADなど「仕様を会話の外へ残す」開発方法を同じ小規模サービスで比較している。共通する考え方は、AIとの会話履歴そのものをプロジェクトの記憶にせず、「何を満たせば完成か」を独立した文書へ固定すること。

### つまり何ができる？

Codexの会話が長くなっても、AIが過去の細部を圧縮・忘却しても、仕様書を読み直せば目的へ戻れる。

### こんな人に役立つ

CodexやClaude Codeで既存プログラムを数日以上触る人。会話が長くなって途中からAIの判断がズレる経験がある人。

### 具体的な使用例

改修前に SPEC.md を作り、「目的」「変更してよい場所」「変更禁止」「入力」「期待結果」「テスト条件」を書く。Codexには毎回このファイルを基準に作業させる。

### 試し方

専用ツールを入れなくてもいい。プロジェクト直下に SPEC.md を1枚作り、次の6項目だけ書く。

- 目的
- 現状
- 変更内容
- 変更禁止
- 完了条件
- テスト方法

そのうえでCodexへ「作業前にSPEC.mdを読み、完了条件を満たすまで作業。仕様変更が必要なら勝手に変えず報告」と指示する。

### 料金・制限・罠

無料。文書が古くなると逆にAIを誤誘導するので、仕様変更時には更新が必要。巨大な仕様書にすると読むコストも増える。

### 検証するとどこまで本当？

比較記事では実装とテストを伴う検証が行われているが、単一の実験であり万能な優劣を証明するものではない。一方、会話とは別に永続的な仕様を置く設計自体は複数ツールで共通している。

**情報源：** Adnan Masood「Specifications as Durable Context for Coding Agents」（2026年10月6日）

> **結月硝子一言：** これは地味だけど効く。AIの記憶力を祈るより、仕様をファイルに書いた方が安い。ソフト開発は数十年かけて「仕様を書け」に到達し、AI時代になってまた同じ場所へ戻ってきた。

## 6. 公開Skills/MCPは「便利そうだから入れる」が危険。AI拡張機能そのものが攻撃経路になっている

**情報の確度：** 確認済みの既知リスク

**難易度：** 今日から運用変更できる

### 何が話題？

AIエージェント向けSkillsやMCP（AIと外部サービスをつなぐ共通規格）が増える一方、偽Skills/MCPを使ってマルウェアを配布する事例や、大量の公開Skillsを調査して多数のセキュリティ問題を見つけた報告も出ている。

### つまり何ができる？

昨日まで「Skillsを使い回すと便利」と紹介してきたが、今日はその裏面。公開Skillはプロンプト集ではなく、コマンド実行や外部通信まで含められる場合がある。ブラウザ拡張機能より権限が強いケースすらある。

### こんな人に役立つ

Claude Code、Codex、Gemini CLIなどへ公開Skill/MCPを追加する人。

### 具体的な使用例

GitHubで「便利なExcel Skill」を見つけても、そのまま会社PCへ入れず、①作者 ②ソース ③実行コマンド ④外部通信 ⑤要求権限を確認してから導入する。

### 試し方

今入れているSkill/MCPを1つだけ選び、READMEではなく実ファイルを確認する。特にインストール時に curl、PowerShell、npm、pipなどで何を取得・実行しているかを見る。

### 料金・制限・罠

無料ツールほど審査主体がいない場合がある。GitHubのスター数や見栄えのいいREADMEは安全性の証明ではない。

### 検証するとどこまで本当？

偽AI拡張をマルウェア配布に利用する攻撃と、大規模Skills監査の問題報告は既に公開されている。ただし「公開Skillは危険」という意味ではなく、通常ソフトと同じく供給元確認が必要という話。

**情報源：** AgentBaiting調査、AI coding skills security audit

> **結月硝子一言：** AI時代になっても「知らない人がネットに置いた実行ファイルを仕事PCへ入れるな」は生き残った。文明は進歩するが、基本ルールは妙にしぶとい。

## 今日の観測

ここ数日の流れをつなぐと、AI活用の差が「どのモデルを使うか」だけでは説明しにくくなってきた。

今日のOracle事例は象徴的で、効果が出ているのは専門家の仕事をAIで再利用可能な手順へ変えた部分。一方でGoogleは複数サービスをまたぐ仕事そのものをエージェントへ預ける方向へ進み、Codex周辺ではWindows固有の不具合や長期作業時の情報管理が実務上の課題として見えている。

つまり、次の段階は「AIへ何を質問するか」ではなく、仕事のどこをAIへ渡し、何を外部ファイルへ固定し、どこで人間が確認するかの設計。

モデル性能が10％上がるニュースより、毎日5回やっているコピペを消す方が年間では効く。AI業界は派手な数字を売りたがるけど、会社員の時間を食っているのはだいたい地味な往復作業。

## 今日ひとつだけ試すなら

自分の定型作業を1つ、AI用の「作業仕様書」にする。

所要10分。追加料金なし。ChatGPTでもCodexでもClaudeでも使える。

1. 毎週または毎月繰り返している作業を1つ選ぶ。

   例：コード調査、Excel確認、会議メモ整理、メール振り分け、資料チェック。

2. ChatGPTへこう入力する。

   この作業を今後AIへ繰り返し依頼できるように、作業仕様書を作ってください。次の6項目に分けてください。目的、入力、確認手順、変更・実行してよいこと、禁止事項、完了条件。曖昧な部分は勝手に補完せず「要確認」としてください。

3. 出てきたものを自分で修正する。
4. SPEC.md や普通のテキストとして保存する。
5. 次回は「この仕様書に従って処理して」と材料と一緒に渡す。

見るべきなのはAIの回答が華麗になったかではなく、自分が毎回説明する量と、AIのやり直し回数が減ったか。そこが減らないなら、その仕様書は役に立っていない。AI活用は儀式ではないので、効かなければ捨てればいい。
