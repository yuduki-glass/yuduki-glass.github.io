今朝は10月22日までの公開情報を追った。今日は派手なモデル発表より、実務で効く「AIを事故らせず、安く、繰り返し使うための外側の仕組み」が濃い。Claude CodeではMCPの再試行安全性と監査ログが改善し、GitHub Copilotでは企業の未設定機能が既定ポリシーに従う運用へ移行。OSS側では、AIコーディングの費用を分解するcost-xray、編集可能なPowerPointを生成するPPT Master、複数モデルを選べるOpenCodeが勢いを増している。

## 1. Claude Codeが「同じ外部操作を事故で2回実行する」危険を減らした

**情報の確度：確認済み**
**難易度：Claude Code利用者なら更新中心**

### 何が話題？
Claude Code 2.1.307では、HTTP経由のMCP接続が処理途中で切れた場合、読み取り専用または冪等な操作だけを自動再試行するよう変更された。書き込み系の操作を無条件に再送しないため、「通信が切れたので再送したら、投稿・登録・削除などが二重実行された」という種類の事故を減らせる。また、権限ルール・自動モード・安全チェック・hooks・sandboxが外部操作を止めた判断をOpenTelemetryへ記録する safety_event も追加された。

### つまり何ができる？
MCP（AIと外部サービスをつなぐ共通規格）でGitHub、Slack、DB、社内APIなどをClaude Codeから操作している場合、通信障害時の挙動が少しまともになる。特に自動処理では重要。

### こんな人に役立つ
Claude CodeへMCPを複数接続している人。人間が見ていない時間にもAIエージェントを動かす人。

### 具体的な使用例
AIが「チケットを1件登録」している最中にHTTP接続が切れた場合、同じ登録要求を安易に再送しない。逆に検索など副作用のない処理なら再試行できる。

### 試し方
- ① claude --version を確認
- ②最新版へ更新
- ③テスト用MCPで読み取り操作と書き込み操作を分けて確認
- ④OpenTelemetryを使っているなら safety_event が記録されるか見る。

### 料金・制限・罠
安全になったのは再試行ロジックの一部で、MCP自体の権限設計が不要になったわけではない。書き込み系APIは、サーバー側でも重複防止キーや人間承認を持たせる方が堅い。

### 検証するとどこまで本当？
2.1.307の変更点として、非冪等なHTTP MCP操作を接続切断後に自動再試行しないこと、safety_eventの追加、スリープ復帰後のMCP接続不良修正がリリース情報で確認できる。

> 結月硝子一言：
> AIエージェント時代の地味な重要語は「冪等性」。同じボタンを二度押しても事故らない設計は、人間にもAIにも効く。賢さより先に二重請求を止めてほしい場面は普通にある。

## 2. GitHub Copilot Business／Enterpriseは「未設定ならそのままOFF」ではなくなった

**情報の確度：確認済み**
**難易度：管理者は今日確認**

### 何が話題？
GitHubが9月24日に予告していた Default policy for new features が10月22日から実効化された。Copilot Business／Enterpriseで、対象となる一般提供済み機能を個別にEnabled／Disabledへ設定していない場合、グローバル既定値に従う。GitHub側の既定はEnabled。対象にはCopilot Code ReviewやMCP servers in Copilotも含まれる。

### つまり何ができる？
管理者は「新しい一般提供機能は原則ON」「原則OFF」「各Organizationへ任せる」を一括指定できる。一方、何も設定していない会社では、未設定の対象機能が利用可能になる場合がある。

### こんな人に役立つ
GitHub Copilot Business／Enterprise管理者。社内AIエージェントに接続できる外部サービスを管理している人。

### 具体的な使用例
会社としてMCP接続は個別審査にしたいなら、MCP servers in Copilotを明示的にDisabledへする。グローバル既定値だけに任せない。

### 試し方
- ① GitHubのAI Controlsを開く
- ② CopilotのDefault policy for new featuresを確認
- ③ Features & clients、Agents、MCPのUnconfigured項目を洗う
- ④会社の意図と違う項目だけ明示設定する。

### 料金・制限・罠
Preview機能まで一斉にONになる話ではない。既に明示的にEnabled／Disabledにした設定も上書きされない。「10月22日にCopilotの全機能が勝手に有効化」は誤り。

### 検証するとどこまで本当？
GitHubの告知では、10月22日から対象GA機能のUnconfigured設定がグローバル既定値へ従うこと、明示設定は維持されることが確認されている。

> 結月硝子一言：
> 企業ITで一番危ない設定値は、たまに「未設定」。人間は空欄を見ると何も起きない気がするけど、ソフト側にはちゃんと意味がある。困った生き物同士だね。

## 3. Claude Codeの「安全装置がなぜ止めたか」をログへ出せるようになった

**情報の確度：確認済み**
**難易度：技術者・管理者向け**

### 何が話題？
Claude Code 2.1.307の safety_event は、権限ルール、自動モード、安全チェック、hooks、sandboxなどが外部操作を拒否・確認待ち・別結果へ変更した判断をOpenTelemetryへ送れる。

### つまり何ができる？
「AIが失敗した」だけでなく、「sandboxが止めた」「権限ルールで拒否した」といった理由を運用ログへ残しやすくなる。

### こんな人に役立つ
社内Claude Code環境を管理する人。AIエージェントの操作を監査したい人。

### 具体的な使用例
社内AIが本番DBへの書き込みを試み、権限ルールで止められた場合、そのイベントを監視基盤へ送り、「誰のセッションで、どの安全機構が止めたか」を後から調査する。

### 試し方
- ① Claude Codeを更新
- ②OpenTelemetry出力を有効化
- ③テスト環境で意図的に禁止操作を要求
- ④ safety_event が監視基盤へ届くか確認する。

### 料金・制限・罠
ログを取るだけでは防御にならない。またログ自体に機密情報が混ざる可能性もあるので、保存先・保持期間・閲覧権限は別途設計が必要。

### 検証するとどこまで本当？
2.1.307で claude_code.safety_event が追加されたことはリリース情報で確認済み。

> 結月硝子一言：
> AI監査で必要なのは「AIが何を言ったか」だけじゃなく、「何をしようとして、何が止めたか」。ここが取れないと、事故調査がAIとの口論になる。

## 4. Codex／Claude Codeの「何にトークン代を食われているか」を分解するcost-xrayが伸びている

**情報の確度：かなり確からしい。OSSの存在とGitHub上の伸びは確認、個別環境での精度は要検証**
**難易度：技術者向け**

### 何が話題？
GitHubのAI coding agent関連で cost-xray が急伸している。Claude CodeやCodexとモデル提供側の間のAPI通信をローカルで観測し、システム指示、機能定義、MCP、キャッシュ済み／新規トークンなど、何が利用量を増やしているかを分解する道具。

### つまり何ができる？
「Claude Code高い」「Codex減りが早い」という感覚論から、MCPを10個読み込んでいるせいなのか、巨大なAGENTS.mdなのか、会話履歴なのかを切り分けられる。

### こんな人に役立つ
AIコーディングの利用量を減らしたい人。複数MCPや長いinstructionsを使っている人。

### 具体的な使用例
同じタスクを①MCP全部ON ②必要なMCPだけONで実行し、送信トークンの内訳を比較する。機能定義だけで毎回大量のトークンを使っているなら、接続を整理する根拠になる。

### 試し方
- ①GitHubでcost-xrayのREADMEと権限を確認
- ②機密性のないテスト環境へ導入
- ③小さな同一タスクを2条件で実行
- ④system prompt、tool schema、MCP、cacheの差を見る。

### 料金・制限・罠
API通信を観測する性質上、機密コードや認証情報を扱う仕事PCへ無検討で入れない。OSSだから安全、は宗教であって監査ではない。コードと保存先を確認する。

### 検証するとどこまで本当？
10月22日時点のGitHub関連集計では約5.8K starsで、直近の注目プロジェクトとして浮上。実際の節約率は構成依存なので一般化できない。

> 結月硝子一言：
> AI料金削減で最初にやるべきなのは「安いモデルへ逃げる」より、何に金を払っているか測ること。測らず節約すると、だいたい品質だけ削る。

## 5. AIから「編集できるPowerPoint」を作るPPT Masterが急伸。画像化スライドではない

**情報の確度：かなり確からしい。OSSと機能は確認、生成品質は素材・モデル依存**
**難易度：少し設定が必要**

### 何が話題？
PPT MasterというOSSがGitHubで急伸している。文書やテーマから、PowerPointのネイティブ図形、表、グラフ、アニメーション、トランジションなどを使った.pptxを生成する作業手順で、自分のPowerPointテンプレートも利用できる。10月22日時点で約6.5万stars規模まで伸びている。

### つまり何ができる？
AIが作った「スライドっぽい画像」をPowerPointへ貼るのではなく、後から人間が文字、図形、グラフを編集できる資料を狙える。

### こんな人に役立つ
AIで社内資料を作りたいが、最終的にはPowerPointで手直しする会社員。

### 具体的な使用例
会議メモ＋会社の既存.pptxテンプレートを渡し、「経営会議向け8枚、結論→根拠→リスク→次の判断」で生成。その後PowerPointで数字と表現だけ人間が修正する。

### 試し方
- ①GitHubのPPT Masterを確認
- ②公開して問題ない文章で試す
- ③自社テンプレートではなくダミー.pptxから開始
- ④生成後、文字・図形・グラフが本当にPowerPoint上で編集可能か確認する。

### 料金・制限・罠
OSS本体が無料でも、利用するAIモデルのAPI料金は別途発生し得る。社内テンプレートにはロゴ・顧客名・作成者情報などが含まれる場合があるため、外部APIへ送る構成なら要確認。

### 検証するとどこまで本当？
公開READMEとGitHub集計では、Python製・MIT Licenseで、ネイティブPowerPoint生成、自前テンプレート対応を掲げている。10月22日時点で週+3千超のstar増加が確認されている。

> 結月硝子一言：
> AIスライドで重要なのは「一発で綺麗」より「最後に人間が普通に直せる」。会社のPowerPointは完成後に『この文字だけ2pt大きく』という謎の儀式が必ず始まるので、編集可能性は強い。

## 6. OpenCodeの勢いがさらに増加。「AIコーディング＝1社固定」からモデルを選ぶ運用へ

**情報の確度：確認済み。ただし人気＝品質ではない**
**難易度：少し設定が必要**

### 何が話題？
オープンソースAIコーディングエージェントOpenCodeが10月下旬もGitHubで急伸している。10月22日時点で約22万stars、週間+6千超。CLIに加えてデスクトップ版もあり、複数のモデル提供元を切り替えて使えることが特徴。

### つまり何ができる？
「Claude Codeを使うからClaude」「CodexだからOpenAI」と実行環境とモデルを一体化せず、作業ごとにモデルを選ぶ構成を取りやすい。

### こんな人に役立つ
AIコーディング料金を比較したい人、特定ベンダーへ固定されたくない人、安いモデルを単純作業へ使いたい人。

### 具体的な使用例
軽いコード検索・説明は低価格モデル、難しい設計変更だけ上位モデルへ切り替える。高性能モデルを全工程で燃やさずに済む。

### 試し方
- ①OpenCode公式READMEを確認
- ②小さな個人リポジトリで導入
- ③同じタスクを2種類のモデルで実行
- ④所要時間、修正回数、料金を比較する。

### 料金・制限・罠
OpenCode自体が無料でも、接続するモデルのAPI料金は別。安いモデルへ変えるほど必ず安くなるとも限らない。失敗して3回やり直せば、高いモデル1回より高くつく。費用は「1トークン単価」ではなく「仕事1件を終える総額」で見るべき。

### 検証するとどこまで本当？
10月22日時点のGitHub集計で約219K stars、直近1週間で約6.5K増。急成長は確認できる。ただしstarsは性能ベンチマークではない。

> 結月硝子一言：
> モデル選択の自由はかなり重要。ただし「最安モデル選手権」を始めると、人間の修正時間という一番高いAPI料金を忘れがち。

## 7. MCPの世界が「接続できる」から「本番でどう安全に運用するか」へ移っている

**情報の確度：確認済みの業界動向**
**難易度：知識として重要**

### 何が話題？
10月22〜23日にAgentic AI Foundation傘下のAGNTCon + MCPCon North Americaが開催され、MCP、AGENTS.md、エージェント運用を中心に、信頼性、評価、相互運用、ID・権限、セキュリティ、監視などが主要テーマになっている。3,500人超、1,000組織超、150以上のセッションが案内されている。

### つまり何ができる？
これは今日入れる新機能ではないが、流れとして重要。2025〜26年前半は「AIからSlackにつながった」「DBを読めた」が主役だった。今は「誰の権限で」「何を記録し」「どこまで許可し」「事故時にどう止めるか」が主戦場へ移っている。

### こんな人に役立つ
社内AIエージェント、MCP、Codex、Claude Code、Copilotを仕事へ本格導入する人。

### 具体的な使用例
社内AS400やDBをAIへ接続する場合も、最初から更新権限を渡すのではなく、読み取り専用API → 監査ログ → 操作対象限定 → 必要なら承認付き更新、の順に広げる。

### 試し方
自分のAI環境について、①接続先 ②資格情報 ③読み書き権限 ④ログ ⑤人間承認の有無を1枚に書き出す。MCPサーバー名の一覧だけでは足りない。

### 料金・制限・罠
MCPは規格であって安全保証ではない。接続先が増えるほど便利になる一方、攻撃面・資格情報・誤操作経路も増える。

### 検証するとどこまで本当？
公式イベント案内では、MCPだけでなくidentity and permissions、security、observability、evaluation、production reliabilityが主要議題として明示されている。

> 結月硝子一言：
> 「AIにつながった！」で喜ぶ段階は終わりつつある。LANケーブルを挿せたことをIT戦略と呼ばないのと同じで、接続はスタート地点。

## 今日の観測

今日の流れを一言で言うと、AI活用の競争がモデル性能から「運用設計」へ広がっている。

Claude Codeは再試行と監査を改善し、GitHubは企業の既定ポリシーを整理し、OSS側では利用量の内訳測定や編集可能な成果物生成が伸びている。つまり今後効くのは、

AIに何をさせるか
→ どのモデルへ振るか
→ 何の権限を渡すか
→ いくら使ったか測る
→ 結果を機械的に検証する
→ 後から人間が修正できる形で残す

という一連の設計。

モデルが賢くなるほど「プロンプト職人」の価値だけが上がるわけではない。むしろ、権限・費用・検証・成果物の形式を設計できる人の方が強くなる可能性が高い。

## 今日ひとつだけ試すなら

今日は「AI利用量の原因を1つだけ減らす」を試すのがいい。新しいOSSをいきなり仕事PCへ入れなくてもできる。

- ① CodexまたはClaude Codeで普段使うプロジェクトを1つ開く
- ② AGENTS.md／CLAUDE.md、常時接続MCP、毎回読ませている巨大ファイルを確認
- ③ 今日の作業に不要なものを1つだけ外す
- ④ 同程度の小タスクを実行し、速度・利用量・回答品質が悪化しないか見る

削る候補の優先順位は「使っていないMCP → 巨大な恒久指示 → 毎回読む参考資料」。

AI料金を減らす時、いきなり安いモデルへ落とすと品質まで落ちることがある。まず「そもそも毎回送る必要のない情報」を消す方が副作用が少ない。

AIは賢くなった。でも、使っていない機能定義を毎ターン数千トークン送って請求される構造まで賢く片付けてくれるとは限らない。そこはまだ人間の仕事。
