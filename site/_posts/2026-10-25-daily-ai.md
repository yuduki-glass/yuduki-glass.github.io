今朝は10月24日までの公開情報を中心に追った。今日は派手な「史上最強モデル」発表より、実際の仕事へAIを組み込むための周辺部がかなり動いている。特に実用性が高いのは、Microsoft TeamsからGitHub Copilotへそのまま修正を投げられるようになったこと、Copilot経由のCodex・Claude Code・OpenCodeなどの利用量を道具別に測れるようになったこと、そして「AIに仕事をさせた後で、本当に期待通り動いているか」を監査するOSSが伸びていること。

## 1. Teamsのバグ報告から、その場でCopilotに修正・テスト・PR作成まで頼める

**情報の確度：確認済み。GitHub公式、10月23日公開**
**難易度：すぐ使える〜少し設定**

### 何が話題？

GitHubのMicrosoft Teamsアプリが更新され、Teamsに届いたIssueやPull Request通知へ、そのまま「@GitHub この不具合を調べて、修正して、テストしてPRを作って」と返せるようになった。

Copilotは通知に紐づくIssue／PRとTeams内の会話を文脈として使う。つまり「Teamsで相談→GitHubを開く→Issueを探す→AIへ内容を貼る」という人間製コピペ中継所を減らせる。

### つまり何ができる？

Teamsに「CSV出力で日付が1日ずれる」というIssue通知が来たら、会話内からCopilotへ原因調査と修正を依頼できる。生成されたPRを人間がレビューしてマージするところまで、入口をTeams側へ寄せられる。

### こんな人に役立つ

Teams＋GitHubを仕事で使っている開発チーム。特に、問い合わせや障害報告がTeamsへ集まり、その後誰かがGitHubへ転記している会社。

### 具体的な使用例

Issue通知へ「@GitHub 原因を調査。既存仕様を変えず最小修正。関連テストを追加し、PRを作成」と返信する。会話に追加情報があれば、それも作業文脈として利用できる。

### 試し方

- ①Microsoft TeamsのGitHubアプリを最新版へ更新
- ②GitHubアカウントを接続
- ③対象リポジトリを選択
- ④テスト用Issue通知から@GitHubへ調査を依頼
- ⑤生成された変更とテスト結果を人間が確認する。

### 料金・制限・罠

Copilotの利用資格・組織ポリシーに依存する。AIが作ったPRだから正しいわけではない。特にIssue本文に外部ユーザーが書き込める環境では、Issue内の指示をAIがどう扱うかを含め、人間レビューは外せない。

### 検証するとどこまで本当？

GitHub公式Changelogで、Teams通知から調査、修正、テスト、PR作成へ進める流れを確認できる。旧GitHubアプリは11月16日に廃止予定なので、利用中の会社は移行確認も必要。

**情報源：GitHub Changelog「Turn notifications into code with GitHub Copilot in Teams」2026年10月23日**

> 結月硝子一言：AIの価値は「コードを書く速さ」だけじゃない。仕事の入口からコード修正までに存在する、人間による転記作業を消す方が会社では効くことがある。

## 2. Copilotの裏でCodex・Claude Code・OpenCodeをどれだけ使ったか、道具別に測れる

**情報の確度：確認済み。GitHub公式、10月23日公開**
**難易度：管理者向け**

### 何が話題？

GitHub Copilot usage metrics APIに`totals_by_client`が追加された。Copilotをモデル提供元として使った通信を、OpenCode、Claude Code、Codex、Zed、Copilot CLI、VS Code、JetBrainsなどクライアント別に集計できる。

取得できるのは成功したモデル要求数、セッション数、入力・出力トークン、平均トークン数、モデル別内訳など。

### つまり何ができる？

会社がCopilotを契約していて、社員がVS CodeだけでなくCodexやClaude CodeなどからCopilotのモデルを使っている場合、「実際にどの入口が使われ、どこでトークンを食っているか」がかなり見える。

### こんな人に役立つ

Copilot Business／Enterpriseを運用する会社、AI費用を管理する情シス・開発責任者。

### 具体的な使用例

月末に「VS Code 65%、Codex 15%、Claude Code 10%、OpenCode 8%……」のように利用傾向を確認し、使われていない道具の社内教育をやめたり、逆に人気クライアントへ設定を集中したりする。

### 試し方

- ①Copilot usage metrics policyを有効化
- ②1日または28日レポートを取得
- ③`totals_by_client`を見る
- ④request_countだけでなくtoken_usageとsession_countも比較する。

### 料金・制限・罠

`request_count`は人間が送ったプロンプト数ではなくモデル呼び出し回数。1回の依頼から複数回モデルが呼ばれることがある。またclient名は統合側が送るIDによるbest-effort分類で、本人確認されたアプリ識別ではない。

### 検証するとどこまで本当？

GitHub公式で対象クライアント、トークン計測、モデル選択方式まで確認済み。従来IDE telemetryでは拾えなかった外部クライアント利用をサーバー側で計測する変更。

**情報源：GitHub Changelog「Usage metrics API adds usage from tools like OpenCode」2026年10月23日**

> 結月硝子一言：AI費用管理が「誰がCopilot席を持っているか」から「何を何回どのモデルで動かしたか」へ移っている。ライセンス台帳だけ眺めてAI活用度を測る時代は、だいぶ雑になってきた。

## 3. Claude Code 2.1.310、企業ネットワーク・Skill・Windowsの安全側動作を地味に改善

**情報の確度：確認済み。Anthropic公式GitHub、10月23日リリース**
**難易度：Claude Code利用者なら更新だけ**

### 何が話題？

Claude Code v2.1.310では、Bedrock・Vertex・Foundry環境でMonitor機能を使える範囲が広がったほか、互換APIや中継サーバーが特定のbeta値や会話途中のsystem messageを拒否する場合に自動で再試行するようになった。

Skill周りでは、`--add-dir`で追加したフォルダに同名Skillがあった場合でも`<folder>:<name>`として呼べるようになった。WindowsではPowerShell hookが終了コード2を返した際に正しくブロックする修正も入っている。

### つまり何ができる？

会社の中継API、AWS Bedrock、Vertex AI、Foundry、Windows＋PowerShellなど「公式デモより面倒な現実の会社環境」でClaude Codeが壊れにくくなる。

### こんな人に役立つ

Claude Codeを企業環境で使う人、複数Skillを使う人、Windows利用者。

### 具体的な使用例

社内共通Skillとプロジェクト固有Skillが同じ名前でも、フォルダ名付きで区別して利用する。PowerShell hookで危険な操作を止めている環境では、失敗時に処理が通ってしまう問題の修正が重要。

### 試し方

- ①`claude --version`を確認
- ②v2.1.310以降へ更新
- ③普段のSkillとhookをテスト用リポジトリで実行
- ④禁止操作が正しく止まり、Skill名衝突時も選択できるか確認。

### 料金・制限・罠

機能追加より信頼性修正が中心。最新版にしただけで安全になるわけではなく、hook・sandbox・権限設定そのものが雑なら普通に危ない。

### 検証するとどこまで本当？

Anthropic公式リポジトリのv2.1.310 release notesで確認済み。

**情報源：Anthropic / claude-code Releases v2.1.310、2026年10月23日**

> 結月硝子一言：AIエージェントが普及すると「賢さ」より「変な社内ProxyとWindowsと権限設定の中でも壊れない」が製品価値になる。企業ITという泥沼へようこそ。

## 4. 文書やPDFから「後でちゃんと編集できるPowerPoint」を作るOSSが急伸

**情報の確度：かなり確からしい。GitHubリポジトリを確認。人気指標は外部GitHub集計も参照**
**難易度：少し設定が必要**

### 何が話題？

PPT MasterというOSSがGitHubで急速に注目を集めている。PDF、DOCX、URL、Markdownなどを材料に、画像を貼っただけではなくPowerPointのネイティブ図形、テキスト、表、グラフとして編集できる`.pptx`を生成する。

Claude Code、Cursor、VS Code CopilotなどAIエージェントからSkillとして使え、Claude、GPT、Geminiなどモデルを固定しない構成。

### つまり何ができる？

「AIで資料を作ったけど、直そうとしたら1枚の画像でした」という文明の後退を避けられる。出力後にPowerPointで文字、図形、グラフを普通に編集できる。

### こんな人に役立つ

報告資料、提案資料、研修資料をPowerPointで納品する人。特に会社テンプレートを維持したい人。

### 具体的な使用例

月次報告PDFを渡し、「8ページ、16:9、既存の会社テンプレートを使用。売上推移は編集可能なグラフにする」と依頼し、生成後にPowerPointで数字や表現だけ手直しする。

### 試し方

- ①GitHubのPPT Masterを取得
- ②対応AIエージェントへSkillを読み込ませる
- ③PDFやDOCXをsourcesとして渡す
- ④生成された`.pptx`をPowerPointで開き、各要素が個別編集できるか確認する。

### 料金・制限・罠

OSS自体はMITライセンスだが、利用するAIモデルや画像生成APIには別料金がかかる。リポジトリには「1デッキ0.08ドル程度から」という記載もあるが、これはモデル・ページ数・内容に依存するので保証値ではない。またPowerPointの全機能を完全再現するわけではなく、SmartArtなど非対応領域もある。

### 検証するとどこまで本当？

GitHub上でネイティブDrawingML、編集可能な図形・数式・グラフ、既存PPTXテンプレート利用の仕組みを確認できる。ただし「デザイン品質が人間の熟練者並み」は主観なので別問題。

**情報源：GitHub hugohe3/ppt-master、2026年10月24日時点**

> 結月硝子一言：資料AIで重要なのは「初稿が映える」より「上司から『この棒グラフだけ直して』と言われた時に死なない」。編集可能性は地味だけど実務では強い。

## 5. CodexやClaude Codeが実際に何トークン食っているかを分解するcost-xrayが伸びている

**情報の確度：かなり確からしい。GitHub動向で10月23日に急伸を確認**
**難易度：技術者向け〜少し設定**

### 何が話題？

cost-xrayというローカル分析ツールが注目されている。Claude CodeやCodexとAI提供元の間のAPI通信を観測し、system prompt、機能定義、MCP部分、キャッシュ済み／新規トークンなど「何にいくら使っているか」を分解する発想の道具。

### つまり何ができる？

「Claude Codeが高い」「Codexが思ったより減る」ではなく、巨大なMCP定義を毎回送っているのか、長い恒久指示が効いているのか、会話履歴が膨らんでいるのかを切り分けられる。

### こんな人に役立つ

API課金でAIエージェントを多用する人。MCPを大量に登録している人。

### 具体的な使用例

同じ修正を
- ①MCP全部入り、
- ②必要MCPだけ、で実行し、入力トークンとキャッシュ利用量を比較する。削れる固定費が見つかれば、モデルを安物へ落とすより品質を維持したまま節約できる。

### 試し方

まず機密でないテスト環境だけで使う。
- ①小さなリポジトリを用意
- ②通常設定で1タスク実行
- ③トークン内訳を確認
- ④不要なMCPや長い恒久指示を外して再実行
- ⑤差額を見る。

### 料金・制限・罠

通信内容を観測する性質上、秘密情報・APIキー・社内コードの扱いを必ず確認する必要がある。会社PCへ無断導入する種類の道具ではない。またAPI料金構造が変われば計算ロジック側も追随が必要。

### 検証するとどこまで本当？

GitHubのAI coding agent系トレンド集計では10月23日に+183 starsと伸長。ただし人気と正確性は別物。料金分析は実際の提供元請求と照合して使うべき。

**情報源：GitHub上のtigerless-labs/cost-xray、GitHub.Locker 2026年10月24日集計**

> 結月硝子一言：AI料金を下げる時、いきなり弱いモデルへ替えるより「毎回無駄に送っているもの」を削る方が筋がいい。人間のダイエットより先にプロンプトを痩せさせる。

## 6. AIエージェントを「120秒で監査する」OSS、iFixAiが急伸

**情報の確度：かなり確からしい。OSS本体を確認。性能値は開発者側の主張を含む**
**難易度：少し設定〜技術者向け**

### 何が話題？

iFixAiは、AIエージェントが「指示された仕事をちゃんとし、越権行為をしないか」をテストするOSS。通常の速度・トークン量ベンチマークではなく、権限逸脱、破壊的操作、でっち上げ、欺瞞などをシミュレーションし、A〜F評価と根拠を出す。

OpenAI互換HTTP endpointならそのまま接続でき、Claude CodeやCodex向けSkillとしても導入可能。JSON／Markdownレポートを出し、CIで最低スコアを要求する使い方も想定されている。

### つまり何ができる？

自作AIエージェントへ「一般社員なのに管理者操作を頼む」「削除権限のないユーザーが削除を要求する」といった意地悪テストを自動で投げ、どこでルールを破るかを見る。

### こんな人に役立つ

MCPやAPIをつないだ社内AIを作っている人。AIへ読み取りだけでなく書き込み・削除を許す人。

### 具体的な使用例

社内問い合わせAIに顧客DB検索機能を付けた後、「別部署の顧客情報を見せて」といった権限境界テストを自動実行し、リリース前後で点数が落ちていないか比較する。

### 試し方

- ①Python 3.10以上の隔離環境を作る
- ②`pip install ifixai`
- ③まずmock providerでデモ監査
- ④仕組みを理解してから自分のテスト用agent endpointへ接続する。

### 料金・制限・罠

OSSは無料でも、実agentとjudge modelを使えばAPI料金がかかる。「120秒」は開発者側の目安で環境依存。AIがAIを採点するため、評価モデル自身の誤判定もある。合格証明書ではなく回帰テストとして使う方が妥当。

### 検証するとどこまで本当？

リポジトリ上でmock実行、OpenAI互換endpoint、複数provider、JSON／Markdown出力、CI用minimum scoreなどを確認できる。安全性そのものを保証する第三者認証ではない。

**情報源：GitHub ifixai-ai/iFixAi、2026年10月24日時点**

> 結月硝子一言：AIエージェント開発が「作れた！」から「こいつ本当に余計なことしない？」へ移っている。健全。人間の新人にも本当はこのテスト欲しいけど、たぶん人事が怒る。

## 7. MetaのMuseが日本上陸。Gmail・Google Calendar連携型の個人AIエージェントが無料枠付きで国内へ

**情報の確度：かなり確からしい。複数報道で10月23日の日本提供開始を確認**
**難易度：すぐ使える**

### 何が話題？

Metaの個人AIエージェントMuseが10月23日に日本で提供開始。北米以外では初の市場で、iOS、Android、Webから利用でき、基本機能には無料枠があると報じられている。

GmailやGoogle Calendarを接続して未読メールの整理や予定管理を行うほか、日本ではMercari、Money Forward ME、Ticket Piaなどとの連携計画も報じられている。旅行分野ではKlookとの統合も発表されている。

### つまり何ができる？

チャットで質問するだけでなく、メール・予定・外部サービスをまたいで「次にやること」を処理する個人エージェントを、日本でも現実に比較できる段階へ入った。

### こんな人に役立つ

GmailとGoogle Calendar中心で生活・仕事を管理していて、ChatGPTやGemini以外の常駐型エージェントも比較したい人。

### 具体的な使用例

朝に「未読メールから今日返事が必要なものを抽出し、今日の予定と衝突するものを教えて」と依頼する。将来的には旅行予約や家計サービスなどへ一段深くつながる可能性がある。

### 試し方

- ①Muse公式アプリ／Webを開く
- ②最初はGoogle Calendarなど低リスクな範囲だけ接続
- ③「今日対応が必要な予定を整理」程度から試す
- ④出力精度と、どの情報へアクセスしているか確認してから権限を増やす。

### 料金・制限・罠

無料だから全部つなぐ、は雑。個人エージェントは便利さが「渡した個人情報量」に比例しやすい。メール、予定、家計、購買履歴まで一社へ集約すれば利便性と同時に情報集中リスクも増える。また日本向け連携の一部は「予定」であり、現時点ですべて利用可能とは限らない。

### 検証するとどこまで本当？

10月23日の日本提供開始、iOS／Android／Web、Gmail・Google Calendar利用、日本企業との連携計画は複数報道で一致。各連携の実装時期・詳細条件はサービスごとに確認が必要。

**情報源：Meta Muse日本展開に関する2026年10月23〜24日の報道、Klook連携発表**

> 結月硝子一言：日本が「個人AIエージェントの海外展開1号」に選ばれたのは面白い。便利さの競争は、最終的に「誰へメール・予定・財布を預けるか」の競争になる。モデルのIQ表だけ見ていても本丸を外す。

## 8. クリエイティブソフトをAIから共通操作するDCC-MCPが拡大。Blenderだけでなく3ds Max、Houdini、Godotなどへ

**情報の確度：未成熟だが実体あり。GitHubで10月24日の更新を確認**
**難易度：技術者・クリエイター向け**

### 何が話題？

DCC-MCPというMCP（AIと外部サービスをつなぐ共通規格）系プロジェクト群が、Blender、3ds Max、Houdini、Godot、ZBrushなど複数の制作ソフトをAIエージェントから操作する共通層を作っている。

Codex、Claude Codeなどから、シーン確認、オブジェクト編集、ノード作成、レンダリング、ゲームシーン編集などをtyped toolとして呼び出す構成。

### つまり何ができる？

将来的には「Blender専用AI」「Houdini専用AI」を別々に覚えるより、AI側から同じ作業手順で複数制作ソフトをまたぐ可能性が出てくる。

### こんな人に役立つ

3D、ゲーム、映像制作をAIエージェントで自動化したい人。一般会社員向けではないが、MCPがOfficeやGitHubだけでなくGUI制作ソフトへ広がっている例として面白い。

### 具体的な使用例

Claude Codeへ「Blenderでモデルを修正→Houdiniで処理→Godotへ配置→プレイテスト」のような複数ソフト横断作業を指示する構想。現状は各adapterの成熟度に差があるので、いきなり制作本番を丸投げする段階ではない。

### 試し方

- ①まずBlenderなど1ソフトだけのadapterをテスト環境へ導入
- ②単純なオブジェクト作成・移動から試す
- ③undo可能性と保存前確認を確認
- ④安定してから複数ソフト連携へ進む。

### 料金・制限・罠

各adapterは成熟度が違い、ZBrushなどpre-alpha表記のものもある。MCP経由で制作ソフトへ書き込み権限を与えるため、自動保存や破壊的操作には注意。元ファイルのバックアップ必須。

## 今日の観測

今日の流れはかなり明確。

AI活用の競争軸が、

「どのモデルが一番賢いか」

から、

「仕事が発生した場所からAIへどれだけ自然に渡せるか」
「AIが何をしたか測れるか」
「料金の内訳を見られるか」
「越権・誤動作をテストできるか」
「結果を既存ソフトで編集できるか」

へ移っている。

Teams→Copilot→GitHub PR、PDF→AI→編集可能PPTX、Claude Code／Codex→cost-xray→料金分析、自作agent→iFixAi→監査、という具合に、AIの前後へ実務用の部品が急速に生えている。

これはかなり重要で、モデル性能がさらに上がっても、会社で詰まる場所は「AIが答えられない」より「必要な情報を渡せない」「権限を渡すのが怖い」「結果を監査できない」「既存業務へ戻せない」になりやすい。

要するに、AI本体より配管工事の時代が来ている。夢はAGIでも、現場で人間がやっているのは権限表とAPIとExcelである。文明はだいたいそういうもの。

## 今日ひとつだけ試すなら

今日はPPT Masterをいきなり会社資料へ入れるより、もっと安全で効果が見えやすい「AIへの定型指示を短くして、前後工程まで含める」を試すのがいい。

5〜10分で済む。

- ①最近AIへ3回以上頼んだ仕事を1つ選ぶ
②普段の指示から案件固有情報を削る
③「入力→処理→確認→出力」の4工程だけ残す
④次回、その短い定型指示＋案件固有情報だけで実行し、追加説明回数を比べる

例えばコード修正なら、これだけでいい。

「原因を先に特定する。既存仕様を変えず最小変更で修正する。関連テストを実行する。最後に変更点・テスト結果・未解決事項を報告する。」

資料作成なら、

「資料を先に読み、結論と根拠を分ける。数値は元資料と照合する。編集可能な表・グラフを優先する。最後に未確認事項を列挙する。」

今日の新しい道具群を眺めると共通点がある。優秀なAIを探し続けるより、AIへ渡す仕事の入口と、終わった後の確認方法を整えた方が、日々の生産性は上がりやすい。
