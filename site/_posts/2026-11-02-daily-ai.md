## 1. 【10/31更新】Claude Code 2.1.316、サブエージェントの思考量指定・チーム共通予算・重ね掛けポリシーを追加

**情報の確度：確認済み**

### 何が話題？

Claude Code 2.1.316が10月31日に公開された。サブエージェントのeffortを個別指定する仕組み、Claude apps gatewayでグループ共通の月額予算を持たせる機能、複数の管理ポリシーを重ねて適用するlayered modeなどが追加された。バックグラウンドのshellプロセスが異常終了後に残る問題や、制限モード周辺の修正も含む。

### つまり何ができる？

メインのClaude Codeは深く考えさせつつ、単純な調査を担当するサブエージェントは軽い思考量にする、といったコスト配分がしやすくなる。企業では「開発部全体で月○ドルまで」という共通予算も作れる。

### こんな人に役立つ

Claude Codeで複数エージェントを使う人、企業でClaude Codeの利用額や権限を管理する情シス。

### 具体例

コード修正本体は高いeffort、テストログの分類担当は低いeffortに固定し、単純作業へ計算資源を使いすぎないようにする。

**難易度：個人利用は少し設定。gateway管理は技術者向け。**

### 試し方

- ①Claude Codeを最新版へ更新 
- ②サブエージェントを使っている場合はCLAUDE_CODE_SUBAGENT_EFFORTを確認 
- ③同じ作業を従来設定と比較 
- ④品質と利用量を見る。

### 料金・制限・罠

予算機能はClaude apps gatewayを使う組織向け。一般ユーザーのClaude料金が安くなった話ではない。

### 検証するとどこまで本当？

公式changelog由来の変更を複数のリリース追跡サイトでも確認。性能向上の話ではなく、主に運用・統制・信頼性の更新。

**情報源：Claude Code changelogを追跡するClaude Network / Aftergradient。**

> 結月硝子一言：AIエージェント時代のコスト削減は「安いモデルを探す」だけじゃなく、「雑用係に最高級の脳を渡さない」が効いてくる。

## 2. 【一般提供】Google Gemini APIのComputer UseがGA。ブラウザ画面を操作するAIを正式運用へ移しやすく

**情報の確度：確認済み**

### 何が話題？

Googleは10月30日、Gemini APIのComputer Useを一般提供（GA）へ移行した。Interactions APIとGenerateContent APIの双方から利用できる。

### つまり何ができる？

APIが用意されていないWeb画面でも、AIに画面を見せてクリックや入力を行わせるエージェントを作れる。PreviewではなくGAになったことで、検証止まりだった企業が本番候補として評価しやすくなった。

### こんな人に役立つ

ブラウザ上の定型作業を自動化したい人、古い業務Webシステムを抱える情シス・開発者。

### 具体例

毎朝管理画面へログイン→CSVをダウンロード→別システムへ転記、のような「APIがないから人間がクリックしている仕事」の自動化候補になる。

**難易度：技術者向け。**

### 試し方

- ①Google AI for DevelopersのComputer Useドキュメントを確認 
- ②テスト用Web環境で読み取り中心の作業を作る 
- ③送信・削除・購入など重要操作には人間承認を入れる 
- ④失敗時の挙動を確認する。

### 料金・制限・罠

画面操作AIはUI変更、ポップアップ、ログイン状態で壊れやすい。APIが存在する処理までComputer Useへ寄せるのは、たいてい遅くて不安定。

### 検証するとどこまで本当？

Google公式Gemini API Release notesで10月30日のGAを確認済み。

**情報源：Google Gemini API Release notes**

> 結月硝子一言：APIがあるならAPIを使う。ないなら画面をAIに触らせる。この順番を逆にすると、未来っぽいけど壊れやすい自動化が完成する。

## 3. 【ベータ】Google「Gemini API CLI」、CodexやClaude CodeからGeminiの画像生成・PDF分析・Deep Researchを直接呼び出せる

**情報の確度：確認済み**

### 何が話題？

Googleは10月27日、Gemini API CLI（gemini-api）をベータ公開した。これはGemini CLIとは別物で、AIエージェントやスクリプトからGemini APIをshellコマンドとして呼ぶための道具。Codex、Claude Code、Cursorなどから利用できる。

### つまり何ができる？

普段のコーディング担当をCodexのままにして、「このPDFだけGeminiで分析」「画像生成だけGemini」「Deep ResearchだけGemini」のように他AIを道具として呼べる。AIを乗り換えるのではなく、得意分野だけ借りる発想。

### こんな人に役立つ

CodexやClaude Codeを使いながらGeminiも組み合わせたい人。複数AIをAPIで自作連携するのが面倒な人。

### 具体例

Codexへ「このPDFをgemini-apiで分析して要点をMarkdownに保存、その結果を使ってC#の仕様書を作って」と依頼する。

**難易度：少し設定が必要。**

### 試し方

- ①gemini-apiを導入 
- ②GEMINI_API_KEYを安全に設定 
- ③`gemini-api analyze -i ./sample.pdf "重要点を3つ"`のような小さな処理を試す 
- ④CodexやClaude Codeから同じコマンドを呼ばせる。公式は自動化環境ではバージョン固定も推奨している。

### 料金・制限・罠

CLI自体はオープンソースのベータだが、呼び出すGemini APIの利用料金は別。インラインファイルは14MBまで。ベータなのでマイナーバージョン間でも破壊的変更があり得る。

### 検証するとどこまで本当？

Google公式Release notesとCLIガイドで確認済み。

**情報源：Google Gemini API CLI公式ガイド**

> 結月硝子一言：今日の業務枠で個人的に一番面白い。AI同士を会議させる大げさな仕組みより、「Codexが必要な時だけGeminiをコマンドとして呼ぶ」の方がずっと実用的。

## 7. 【実験枠】Runtime Cloud MCP、Codex・Claude Codeから外部実行環境を1コマンド接続。ローカルPCに処理を抱えない構成を試せる

**情報の確度：かなり確からしい。公式ドキュメントは確認済みだが、新興サービスなので長期運用実績は未評価。**

### 何が話題？

Runtime CloudのMCPドキュメントが10月31日に更新され、Claude CodeとCodexから`npx -y withruntime mcp`を使って接続する手順が公開されている。MCP経由で同社の外部実行環境をAIの道具として扱う構成。

### つまり何ができる？

CodexにローカルPC上ですべてを実行させず、隔離したクラウド環境へ処理を投げる構成を比較的少ない設定で試せる。

### こんな人に役立つ

AIエージェントにコードを実行させたいが、自分のPCや本番環境を直接触らせたくない開発者。

### 具体例

Codexに怪しい依存関係を含むサンプルコードを解析させる際、ローカルではなく一時的な外部環境で実行する。

**難易度：技術者向け。**

### 試し方

- ①テスト用Codex環境を用意 
- ②`codex mcp add runtime -- npx -y withruntime mcp`で登録 
- ③低リスクなコード実行を依頼 
- ④権限・課金・ログの残り方を確認する。

### 料金・制限・罠

新興サービスへコードやデータを渡すことになる。会社のソースや秘密情報をいきなり投入しない。MCPで接続できることと、企業利用に適することは別問題。

### 検証するとどこまで本当？

接続方法は公式ドキュメントで確認。第三者による十分な安全性・信頼性評価は今回確認できなかった。

**情報源：Runtime Cloud MCP documentation**

> 結月硝子一言：今日の実験枠。『AIに実行権限を与えたい。でも俺のPCではやるな』という、ごく健全な恐怖心を構成に落とす発想。

### つまり何ができる？

『アレクサ、照明をつけて』の決め打ちから、『ちょっと暗い』『寝る準備したい』のような自然な会話を起点に家の操作へつなげる方向へ変わる。

### こんな人に役立つ

Echo、Fire TV、Alexa対応家電を使う家庭。特にPrime会員。

### 具体例

一度『アレクサ』と呼んだ後、そのまま追加質問を続ける。記念日や好みを覚えさせ、後の会話へ利用することもAmazonが案内している。

**難易度：すぐ使える。ただしEarly Accessの順次案内待ち。**

### 試し方

- ①Alexa+ Early Accessへ申し込む 
- ②対応端末を確認

Early Access無料。正式提供後はPrime会員追加料金なし、非Prime月3,000円。食べログ、Uber Eats、出前館、チケットぴあ等との連携は『今後提供予定』で、現在すべて使えるわけではない。

## 今日の観測

今日いちばん実務的なのは、AIを一つに統一する流れより『普段のAIから別AIを道具として呼ぶ』流れ。Gemini API CLIはその典型で、Codexを主役にしたまま、PDF解析・画像生成・Deep ResearchだけGeminiへ投げられる。MCPも同じで、AIを乗り換えるより能力を外付けする方向がかなり現実的になってきた。

もう一つは管理機能の成熟。Claude Codeのグループ予算、GitHub Enterpriseの従量予算、Microsoft Copilotの監査証跡を見ると、企業AIは『使えるか』の段階から『誰に、いくら、何をさせ、後から説明できるか』へ移っている。会社で本格導入するなら、モデル性能よりこっちが効く。

生活側はSiri AIとAlexa+が同じ週に日本へ着弾している。スマホと家という二大インターフェースが生成AI化したので、2026年10月末は後から振り返ると『AI専用アプリから生活OSへ移った時期』として結構分かりやすい節目になりそう。

## 今日ひとつだけ試すなら

今日はGemini API CLI。理由は、CodexやClaude Codeを捨てずに別AIの能力を足せるから。

- ① Gemini API CLI公式ガイド を開く
- ② テスト用のGemini APIキーを設定する
- ③ 機密情報を含まないPDFで `gemini-api analyze -i ./sample.pdf "重要点を3つにまとめて"` を実行する
- ④ 次にCodexへ『このPDFはgemini-apiで解析して、その結果を使って作業して』と依頼し、Codex単体との違いを見る

最初から大掛かりなマルチAI基盤を作る必要はない。普段使っているAIに一個だけ外部の道具を持たせて、本当に便利か確認する。それで効かなければ捨てる。このくらい雑に試せるのが、今のAI環境ではむしろ強い。
