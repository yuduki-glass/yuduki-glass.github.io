## ■ 1. GitHub Copilot、チーム単位でプラグインを標準設定

**確度：**確認済み（GitHub公式、11月18日）／**難易度：**管理者向け

### 何が話題？：

組織のチーム管理者が承認済みAgent Pluginを選び、チームの初期設定として配布できるようになった。

### 何ができる？：

新メンバーが個別に同じプラグインを探して設定する手間を減らせる。

### 役立つ人：

GitHub Copilot Business/Enterpriseを複数人で使う開発チーム。

### 具体例：

社内のコード規約確認用プラグインをチーム全員の標準設定にする。

### 試し方：

- ①github.comで組織のTeamを開く
- ②「Customize Copilot」を選ぶ
- ③許可されたプラグインを追加
- ④VS Code・Copilotアプリ・CLIでチームメンバーの初期設定を確認。

### 料金・制限・罠：

Business/Enterprise対象。子チームには継承されない。個人は許可範囲で無効化可能。組織の禁止ポリシーが優先される。プラグイン接続先の別料金は要確認。

### 検証：

配布範囲と権限の優先順位は公式確認。作業時間の削減量は未測定。

**情報源：**<https://github.blog/changelog/2026-11-18-customize-github-copilot-for-your-team/>

## ■ 2. GitHub Team、無料のセキュリティリスク診断を自動実行

**確度：**確認済み（GitHub公式、11月18日）／**難易度：**組織管理者向け

### 何が話題？：

GitHub Team契約の組織で、漏えいした認証情報やコードの脆弱性を調べる無料のリスク評価が自動実行されるようになった。

### 何ができる？：

セキュリティ管理者が危険箇所を把握し、対応順序を決められる。

### 役立つ人：

GitHubで業務用プログラムを管理する組織。

### 具体例：

過去に誤って登録したAPIキーの疑いを確認し、必要ならキーを失効・再発行する。

### 試し方：

- ①GitHub組織のセキュリティ画面を開く
- ②リスク評価の通知・結果を確認
- ③警告対象と影響範囲を調査
- ④修正後に再確認。

### 料金・制限・罠：

診断自体は無料と公式記載。ただしGitHub Teamの契約は必要。診断結果がゼロでも安全の保証にはならない。認証情報が漏れた場合、コードを消すだけでは不十分。

### 検証：

自動実行と無料評価は公式確認。検出率は未検証。

**情報源：**<https://github.blog/changelog/2026-11-18-security-risk-assessments-run-automatically-on-github-team/>

> 結月硝子一言：AIでコードを書く速度を上げても、漏れた鍵を放置したら帳消し。

## ■ 3. CopilotがBox・Supabase・Calendlyなど8サービスと接続

**確度：**確認済み（GitHub公式、11月18日）／**難易度：**少し設定が必要

### 何が話題？：

MCP（AIと外部サービスをつなぐ共通規格）の公開プレビュー接続先として、Box、Buildkite、Calendly、ClickUp、Mixpanel、Supabase、Webflow、Wixが追加された。

### 何ができる？：

Copilotの会話から、許可した外部サービスの情報を参照し、対応する操作を進められる。

### 役立つ人：

開発、予定調整、資料管理、Webサイト運用を複数サービスで行う人。

### 具体例：

Supabaseのデータベース構造を調べてから、変更案をCopilotに作らせる。

### 試し方：

- ①CopilotアプリのCustomizeを開く（CLIなら「/mcp」）
- ②Connectorsから対象サービスを選ぶ
- ③接続先の認証・権限を確認
- ④架空データで読み取り操作を試す。

### 料金・制限・罠：

全Copilotプランで公開プレビュー。ただし外部サービス側の契約や権限が必要。Business/Enterpriseでは管理者によるプレビュー許可や接続先許可リストの変更が必要な場合がある。書き込み権限の付与は慎重に。

### 検証：

8サービス、設定経路、対象プランは公式確認。各サービスでの操作成功率は未検証。

**情報源：**<https://github.blog/changelog/2026-11-18-connect-supabase-clickup-buildkite-and-more-to-copilot/>

> 結月硝子一言：連携先が増えるほど便利になる一方、AIに渡す権限の棚卸しも必要になる。

## ■ 4. Gemini 4 NeonがGitHub Copilotに追加

**確度：**確認済み（GitHub公式、11月18日）／**難易度：**対象契約者ならすぐ使える

### 何が話題？：

GoogleのGemini 4 NeonがCopilotのモデル選択に追加。複数工程のコード修正や外部機能利用を想定したモデルで、順次展開される。

### 何ができる？：

同じ開発課題を別モデルで試し、品質と利用費用を比較できる。

### 役立つ人：

Copilotでコード生成・レビューをする人。

### 具体例：

テスト用Python関数の修正を既存モデルとNeonに依頼し、テスト合格数と不要な変更の有無を比較。

### 試し方：

- ①VS CodeなどのCopilotモデル選択を開く
- ②Neonが表示されれば選択
- ③同じテスト課題を実行
- ④変更差分、実行結果、利用料金を比較。

### 料金・制限・罠：

Copilot Pro+、Max、Business、Enterprise対象。使用量に応じた課金で、単価は料金表を確認。無料プランや通常Proは対象として記載されていない。Googleの性能改善主張は独立検証ではない。

### 検証：

対応プラン、対応アプリ、順次展開は公式確認。性能差は未検証。

**情報源：**<https://github.blog/changelog/2026-11-18-gemini-4-neon-in-github-copilot/>

> 結月硝子一言：モデルが増えたこと自体より、同じ課題をいくらで正確に解けるかが重要。
