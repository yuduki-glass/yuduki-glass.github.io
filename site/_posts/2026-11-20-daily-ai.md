## 1. ChatGPT for Accounting

**確度：**確認済み（OpenAI公式）。**難易度：**少し設定が必要。

### 何が話題？

会計向けの専用プラグインと連携手順が公開された。請求書から仕訳案を作り、銀行明細と台帳の差額を探し、月次報告書の下書きまで行える。

### 役立つ人・使用例：

経理担当者がExcelの入金一覧と請求一覧を照合し、金額不一致・重複・未入金の候補を元行番号付きで抽出する。

### 試し方：

- ①ChatGPTデスクトップアプリを開く
- ②利用可能ならPluginsからAccountingを導入
- ③機密情報を除いたサンプル台帳を渡す
- ④「一致・不一致・要確認を分け、元行番号を示して」と指示し、手計算と照合。

### 料金・制限・罠：

プラグインの導入自体は無料。Businessでは導入可能、Enterpriseは管理者承認が必要。利用するAI・外部会計サービスの料金は別。会計処理の確定・送信は人間が承認する。

### 検証：

対応サービスと手順は公式確認。実務上の正答率は未検証。

**情報源：**<https://help.openai.com/en/articles/20001709-using-chatgpt-for-accounting-work>

> 結月硝子一言：自動仕訳より先に「根拠の行番号を必ず出す」を徹底したい。

## 2. Genie 4がAPI・AI Studioへ

**確度：**確認済み（Google、11月19日）。**難易度：**技術者向け。

### 何が話題？

文章や参照画像から720p・24fpsの連続した仮想世界を生成し、キー操作や追加指示で環境を変えられる開発者向け提供が始まった。

### 役立つ人・使用例：

ゲーム開発者が架空の街を作り、雨・照明・障害物を変えながら操作感を試す。猫の行動シミュレーションにも発想上は近いが、長期記憶や社会モデルを自動で保証するものではない。

### 試し方：

- ①Google AI Studioを開く
- ②Genie 4の利用資格を確認
- ③架空の路地の説明文で生成
- ④操作と状態の連続性を確認。

### 料金・制限・罠：

API利用は課金条件を要確認。日本の個別アカウントでの利用可否は未確認。出力にはSynthIDが付く。

### 検証：

API・AI Studio提供は公式確認。長時間の物理的整合性は未検証。

**情報源：**<https://blog.google/innovation-and-ai/technology/developers-tools/genie-4-in-gemini-api/>

## 3. GitHub CLIがイベント待機に対応

**確度：**確認済み（GitHub、11月18日）。**難易度：**技術者向け。

### 何が話題？

gh v2.105.0でプルリクエストの変化をイベントとして待てるようになり、一定間隔で問い合わせ続ける方式を減らせる。

### 役立つ人・使用例：

AIがコード修正のプルリクエストを作成した後、レビューやチェックの変化を待って次の処理に進む。

### 試し方：

- ①gh --versionでバージョン確認
- ②公式変更履歴からイベント待機の構文を確認
- ③テスト用プルリクエストで更新を発生
- ④通知を受けられるか確認。

### 料金・制限・罠：

GitHub CLIは無料。GitHubの権限・API制限は適用される。具体的なコマンド構文はここでは未検証のため記載しない。

### 検証：

イベント待機機能とバージョンは公式確認。

**情報源：**<https://github.blog/changelog/month/11-2026/>

> 結月硝子一言：毎秒「まだ？」と聞く自動化は、機械でも迷惑。

## 4. GitHub EnterpriseのS3監査ログ認証

**確度：**確認済み（GitHub変更履歴、11月19日）。**難易度：**企業管理者向け。

### 何が話題？

GitHub EnterpriseのS3監査ログ転送に使うOpenID Connect認証の対応範囲がGHE.comへ拡大した。

### 役立つ人・使用例：

監査ログをAWS S3に保管する管理者が、長期間有効な固定アクセスキーへの依存を減らす。

### 試し方：

- ①GitHub Enterpriseの監査ログ設定を開く
- ②対象環境がGHE.comか確認
- ③AWS側の信頼設定と権限を検証
- ④テスト転送と監査ログの欠落を確認。

### 料金・制限・罠：

GitHub EnterpriseとAWS S3の利用料が必要。認証方式を変更する前に既存ログの転送停止を避ける手順を準備する。

### 検証：

対応範囲拡大は公式変更履歴で確認。個別環境での設定は未検証。

**情報源：**<https://github.blog/changelog/>
