## 1. Claude Ship

**確度：**確認済み（11月23日発表）。

### 何ができる？

 GitHubの変更提案をClaudeがレビューし、PR Stewardがテスト失敗や指摘への修正を支援。Claude Approvalsは組織の承認ルールに沿って定型変更を承認できる。後二者はベータ。

### 役立つ人：

GitHubでPythonなどを共同開発するチーム。

### 使用例：

修正案をGitHubに出した後、テスト失敗を自動修正し、人間が最終確認する。

**難易度：**少し設定が必要。

### 試し方：

- Claude Team/Enterpriseの管理者がGitHubリポジトリを接続し、Code ReviewとPR Stewardを有効化。最初は承認を観察モードにして挙動を確認。

### 料金・罠：

トークン従量課金。レビューの見落としはあり得る。承認権限とGitHubの保護規則を別々に管理する。

### 検証：

機能と対象プランは公式確認。品質向上の数値は企業自身の実績で、一般化は未検証。

**情報源：**https://claude.com/resources/articles/introducing-claude-ship

> 結月硝子一言：コードを書くAIから、コードを通す工程を支えるAIへ。ただし無人承認は慎重に。

## 2. Gemini APIのファイル部分読み込み

**確度：**確認済み（11月23日発表）。

### 何ができる？

 PDFの特定ページ、表計算のセル範囲、音声・動画の一部分を指定してAIに読ませられる。Office/OpenDocumentファイルの直接アップロードにも対応。

### 役立つ人：

巨大なExcelやPDFをAPI経由で処理する開発者。

### 使用例：

100ページの報告書から必要な3ページだけを抽出・分析。

**難易度：**技術者向け。

### 試し方：

- Google AI StudioのAPI資料でファイル部分指定を確認し、テスト用ファイルで全体読み込みと部分読み込みの使用量を比較。

### 料金・罠：

APIの利用料が必要。正確な節約率はファイル構造次第。通常のGeminiチャットの機能と混同しない。

### 検証：

機能は公式確認。自分のデータでの節約効果は未検証。

**情報源：**https://blog.google/innovation-and-ai/technology/developers-tools/file-slicing-controls/

> 結月硝子一言：モデルを変えるより、不要なデータを読ませないほうが安くなる場面は多い。

## 5. GitHub Copilotクラウド実行の課金

## 6. Slackの秘密情報検知

**確度：**確認済み（11月23日）。

### 何が変わる？

 GitHubのSecret scanningがSlack Incoming Webhook URLの形式を厳密に判定し、誤警告を減らす。

### 役立つ人：

Slack通知をGitHub Actionsなどと連携する管理者。

### 使用例：

偽のWebhook検知で調査時間を浪費しにくくなる。

**難易度：**すぐ使える（検知機能が有効な環境）。

### 試し方：

- リポジトリのセキュリティ警告を確認。実際のWebhook秘密値をテスト用に公開しない。

### 料金・罠：

検知の改善は漏えい防止の保証ではない。

### 検証：

GitHub公式更新履歴で確認。

**情報源：**https://github.blog/changelog/2026-11-23-secret-scanning-reduces-false-positives-for-slack/

> 結月硝子一言：警告は数より精度。

## 7. テスト網羅率レポートの形式チェック

**確度：**確認済み（11月23日）。

### 何が変わる？

 GitHub Code QualityへのアップロードがCobertura XML形式でない場合、成功したふりをせずエラーを出す。

### 役立つ人：

CIで自動テスト結果を管理する開発者。

### 使用例：

網羅率が表示されない原因をログから特定。

**難易度：**技術者向け。

### 試し方：

- GitHub ActionsのCode Qualityログを確認し、形式エラーが出たらテストツールの出力をCobertura XMLに変更。

### 料金・罠：

GitHub Team/Enterprise Cloudなど対象環境限定。Enterprise Serverは対象外。

### 検証：

公式更新履歴で確認。

**情報源：**https://github.blog/changelog/2026-11-23-code-coverage-uploads-now-flag-invalid-report-formats/

> 結月硝子一言：失敗を成功と表示する仕組みほど厄介なものはない。
